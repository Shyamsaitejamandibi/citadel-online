# The living table

The product is focused on gaming. Players bring Discord, Google Meet, or their preferred talking platform; the game interface has no chat composer or voice controls.

## Research and decisions

- [PlayingCards.io](https://playingcards.io/): inspected its room-code entry and synchronized tabletop model. The useful idea is one shared play surface with a private hand, rather than a sequence of disconnected game screens.
- [Colonist](https://colonist.io/): inspected its entry page and prominent friend-play actions. Creating and joining a table should be accessible immediately.
- [Board Game Arena](https://en.boardgamearena.com/): inspected its public game-discovery/learning entry. Keep rules help near actual play, and make the game's state readable.
- [Duolingo exercise on Mobbin](https://mobbin.com/screens/a8836fb1-fcfc-4657-8cbf-775a3facb219): examined its progress, selected answer, and focused confirmation. Applied those patterns to a playable first-turn lesson.
- [Duolingo exercise on Mobbin](https://mobbin.com/screens/9fb54ed6-d4c9-465e-9f54-37d24bc8bcae): examined its single exercise and explicit completion action. The lesson asks the player to make real decisions, one step at a time.

The Discord reference inspected early in research was discarded after the product direction was clarified. No new social or voice backend is included.

These are design interpretations of the inspected references, not claims that our implementation has been proven better than an offline game. Original artwork already present in the repository is reused; reference screenshots are not incorporated into the product.

## Verification

- Engine tests cover every player count and existing character/district interactions, plus ready checks, both practice resource paths, and immutable score forecasts with diversity/unique/completion bonuses.
- Browser tests exercise home/library/mobile fit, independent human seats, drafting/gathering/building/reload, server privacy and stale actions, mobile practice, synchronized readiness, private-plan persistence, focus mode, and a seven-player table with overlap and overflow checks.
- Production build, lint, and TypeScript checks are run before delivery.
- `artifacts/` contains updated desktop/mobile evidence, including seven-player layouts.

## Boundaries

Test bots are intentionally available in online lobbies during testing. Keep them enabled until the owner explicitly says the game is fully ready; deploying the app is not release sign-off. Only the host can add or remove bots, and every human must still mark themselves ready.

This iteration keeps the classic base rules and the existing Convex session model. It does not add expansion characters, public matchmaking, accounts, camera feeds, or voice. Saved plans are browser-local; a room's authoritative state remains on Convex. Catch-up shows updates the live subscription received while hidden, rather than storing a separate long-term replay.
